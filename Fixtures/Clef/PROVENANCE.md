## What each file holds

- **`prompt.json`** — six requests (`cases[].request`) with the reference's exact `input_ids`,
  per-question `question_span`/`option_spans`/`option_ids`, the app-side `state_tokens_*` and
  `state_truncated`, and the reference's own `systemone` body in `observed`.
  Coverage: one per question type; a `choice` whose criteria insertion order differs from the
  id-sorted encode order and that mixes a described option with a bare (`null`) one; a `choice`
  with identical descriptions (the tie case) plus an empty description (`""`); a JSON state with
  non-ASCII keys (`sort_keys` is code-point order); a float-heavy JSON state with nested arrays;
  and a state long enough to truncate at 16,384 tokens.
  The tie case's **observed** answer is the reference's real output — it is the closest the model
  comes to a true tie, not a constructed one; the tie-break rule itself (first inserted option
  wins) is pinned by `ClefAnswerTests` against `clef_mlx.py:524`.
- **`head.json`** — 3 seeded hidden-state cases: the hidden tensor shapes and the
  per-question `logits`/`probabilities` the reference's `JointSchemaHead` produced from them, with
  the spans and the lexical vectors it used.
- **`tokens.json`** (CF-5b) — five full prompts (including an **empty** state and one that
  truncates: 102,800 state tokens, 16,242 kept) with the reference's exact `input_ids` and the
  app-side truncation numbers. Swift must match these ids exactly.
- **`hidden.json`** (CF-5b) — for the same five prompts, the backbone's last-position vector (first
  64 dims and its full L2 norm) plus every question/option span's mean-vector norm, read from the
  reference's text model. These are the vectors the head pools, so they are the parity seam between
  the two runtimes' backbones.
- **`answers.json`** (CF-5b) — 24 single-question records (10 `noul`, 9 `choice`, 5 `score`) over the
  CLM stream's business texts, with the reference's own `systemone` body and unrounded
  probabilities. `closest_margins` lists the four closest calls it contains (the model is confident on
  these texts: the tightest margin available was 0.08, so "near 50/50" in practice means 54/46).
- **`head_inputs.safetensors`** — the *inputs* for `head.json` (documents-shaped): `caseN.hidden`
  (bf16) and `caseN.qM.lexical` (bf16, one mean-pooled output-embedding row set per option span).
  These are activations, **not weights** — the head's 244 MB of weights stay in the installed model
  directory, which is why the golden tests skip when it is absent (`.gitignore` covers a fixture
  holding weights; this one does not need to).

## Reproducing

The model must be installed (Browse → Clef Flash → Install; ≈6.2 GB, 11 files). The script reads
`joint_head_config.json`, `joint_head.safetensors` and the tokenizer from that directory and writes
only under `Fixtures/Clef/`.
