## 0. The reference stack and the rule about fixtures

**Reference = the upstream repo's own handler path, run once, offline, at fixed seeds.** On
Apple Silicon that path is mixed (`code-map.md` §1): the **text encoder and condition encoder run
PyTorch-on-MPS**, while the **DiT and VAE run the native MLX ports**
(`acestep/models/mlx/dit_model.py`, `dit_generate.py`, `vae_model.py`, with their own tests
`dit_generate_sampler_test.py`, `dit_model_static_buffers_test.py`). The PyTorch model classes are
the *specification* where the two differ; the handler path is what the fixtures must reproduce.
The MLX port is therefore a **second opinion for the DiT/VAE only** (same framework family, so
its tolerance can be an order tighter — useful for isolating "is this a Swift bug or an expected
torch↔MLX gap?"); it has no text/condition encoder at all. Which dtype each stage actually runs in
is part of the fixture (`versions.json`), because it decides the tolerance (Q11-7).

A fixture is generated **once**, committed, and never hand-edited. This is the app's own rule
for both existing precedent sets:

- `MLXUITests/Fixtures/RIFE/README.md:3-5` — "Generated **once** … **Never edit these to make
  a change pass**: a mismatch is a `SPEC_QUESTIONS.md` entry, or a bug in `Modules/RIFE`."
- `MLXUITests/Fixtures/Flux2Klein/README-Flux2Klein.md:3-7` — tiny random-init modules from
  the pinned HF classes, fixed seed, "Re-running gives byte-identical files. **Never edit
  these**"; `Flux2KleinGlueTests.swift:193-215` pins each file's SHA-256 and a total-size
  budget, so a hand edit fails CI.
- The repo-wide hard gate (CLAUDE.md, "Never edit a golden or fixture to make a change pass").

Therefore every fixture below names its **generator script** (committed next to the fixtures,
as `make_rife_golden.py` is at `MLXUITests/Fixtures/RIFE/make_rife_golden.py`), its pinned
versions (a `requirements.txt` + `versions.json`, as `MLXUITests/Fixtures/Flux2Klein/versions.json`),
its seed, and its SHA-256 list in the test file.

### Two tiers (the app already uses both)

| Tier | Where | Committed? | Used for | Precedent |
|---|---|---|---|---|
| **Tiny** | `MLXUITests/Fixtures/ACEStep/` | yes, ≤10 MB total (this plan; Flux2Klein's own budget is 2 MB) | every slice's numerics, with random-init modules at tiny dims | `tiny_goldens.py`, `Flux2KleinGlueTests.swift:133-136` |
| **Real** | an owner-run folder, named by an env var | **no** | real-checkpoint parity (bf16/int8/int4), end-to-end audio | `Flux2KleinRealDiTGoldenTests.swift:7-24` (`TEST_RUNNER_MLXUI_TEST_KLEIN_DIT_GOLDEN_DIR`), `RIFEParityTests` enabled only when `MLXUI_TEST_RIFE_DIR` exists (`RIFENetTests.swift:137-170`) |

Real-tier fixtures are generated by the **owner** with the same committed generator script
pointed at the installed weights (exactly the Klein pattern: "from a file the OWNER makes with
… `real_dit_goldens.py` (not committed, not run by the implementer)").
The committed ≤10 MB budget therefore applies to the tiny tier only; the real tier is
env-var-gated and never breaks a clean checkout.

## 1. Component boundaries the fixtures must respect

From the pinned model classes (`acestep/models/turbo/modeling_acestep_v15_turbo.py`):

- **Text encoder** — `Qwen3-Embedding-0.6B`: plain `Qwen3Model`, `hidden_size 1024`, 28 layers,
  16 heads / 8 KV heads, head_dim 128, RoPE θ=1e6, RMSNorm; **last hidden state only**
  (no LM head). Loaded from `Qwen3-Embedding-0.6B/model.safetensors` + its tokenizer.
- **Condition encoder** — `AceStepConditionEncoder` (`:1513`, forward `:1531`) = `text_projector`
  (1024→2048, no bias) + `lyric_encoder` (`:580`, 8 bidirectional layers over *embedding-table*
  inputs 1024→2048) + `timbre_encoder` (`:1000`, 4 layers, input 64→2048, first-token pooled,
  `:1158`: `hidden_states[:, 0, :]`; **no special token** — the cat is commented out `:1087`),
  then `pack_sequences` order **lyric → timbre → text** (`:1553-1556`).
- **DiT** — `AceStepDiTModel` (`:1243`, forward `:1307`): `proj_in` (Conv1d over
  `[context(64+64=128) ‖ x_t(64)]` → 192 in-ch, patch 2), two `TimestepEmbedding`s
  (`:203`; `t` and `t − t_r`), `condition_embedder` 2048→2048, 24 `AceStepDiTLayer`
  (`:446`) alternating `sliding_attention`/`full_attention` (window 128), each layer =
  AdaLN self-attn + AdaLN **cross-attn to the packed encoder states** (K/V cached across
  steps: `past_key_values` is an `EncoderDecoderCache`, self-attn `use_cache=False`
  `:535`-ish) + AdaLN MLP, `norm_out` + `scale_shift_table` + `proj_out`
  (ConvTranspose1d → 64) (`:1494-1500`).
- **Sampler** — `AceStepConditionGenerationModel.generate_audio` (`:1865`): for turbo,
  `infer_steps=8` (**the reference handler's `GenerationParams.shift` default is `1.0`**,
  `inference.py:151`; `:1970-1979` builds `raw = [1 − i/8]`, and with `shift == 1.0` the list is
  exactly `[1.0, 0.875, 0.75, 0.625, 0.5, 0.375, 0.25, 0.125]` — the `turbo-shift3` *separate
  checkpoint family* is the one that uses `3.0`, `SHIFT_TIMESTEPS[3.0]`; `code-map.md` Q5.1).
  Euler ODE, **last step is a direct x0 jump** (`xt = get_x0_from_noise(xt, vt, t)`,
  `:2138-2147`), **DCW wavelet correction is ON by default for turbo**
  (`generate_music.py:181-195` → `is_turbo_model()`; correction after every non-final step
  `:2200-2210` and on the final x0 `:2142-2145`). Turbo is CFG-distilled: **no CFG, no
  unconditional batch** (`generate_music.py:309-318` forces `guidance_scale=1.0`;
  APG/ADG are base-model-only, `code-map.md` Q5.3).
- **VAE** — `diffusers.AutoencoderOobleck` (`vae/config.json`: 48 kHz, 2 ch,
  `downsampling_ratios [2,4,4,6,10]` → hop 1920 = 25 Hz, latent 64-d, dec/enc weight_norm +
  Snake1d). Decode only in v1; encode is needed only for covers/repaint, which v1 does not do.
- **v1 does not need** the `audio_tokenizer` / `attention_pooler` / `ResidualFSQ` /
  `AudioTokenDetokenizer` path *for generated audio*: `prepare_condition` computes
  `lm_hints_25Hz = detokenize(tokenize(...))` and then **throws it away** when
  `is_covers == 0` (`:1650-1690`: `src_latents = torch.where(is_covers > 0, lm_hints_25Hz,
  src_latents)`; text2music → `is_covers` all-zero, `src_latents` is the silence latent,
  `conditioning_masks.py:88-95`). A Swift port may skip tokenize+detokenize for text2music —
  output-identical, but it is a deliberate divergence from a literal port and must be
  recorded (open question Q11-1). If that path is ever needed (covers, LM hints), it is its own
  slice with its own fixtures.

**Inputs for text2music with no LM (the recommended v1 path), all deterministic:**

```
prompt        = "warm lo-fi hip hop, vinyl crackle, mellow rhodes, 82 bpm"   (fixture constant)
lyrics        = "[instrumental]"                                            (upstream's convention, acestep/openrouter_adapter.py:117,233)
instruction   = DEFAULT_DIT_INSTRUCTION = "Fill the audio semantic mask based on the given conditions:"  (constants.py:119)

vocal_language= "en"
duration      = 10.0 s  → T = duration*48_000/1920 = 250 latents           (padding_utils.py:79, conditioning_target.py:64,90)

```
(`DURATION_MIN = 10` s — `constants.py:58-59`; the reference cannot make an 8 s clip, so the
real fixtures use 10 s (T = 250) and the tiny fixtures use T = 16 with a toy VAE hop.)
The rest of the settings, all reference defaults:
```
seed          = 20261107 (any fixed int; the *noise tensor itself* is the fixture input — §3.5)
infer_steps   = 8, shift = 1.0, dcw = on (turbo default), infer_method = "ode", sampler_mode = "euler"
```

The exact formatted strings come from `SFT_GEN_PROMPT` (`constants.py:160-168`) and
`_format_lyrics` (`prompt_utils.py:38-40`): `text_prompt = SFT_GEN_PROMPT.format(instruction,

Both are tokenized with the **same Qwen3 tokenizer**, max_length 256 / 2048
(`conditioning_text.py:130-150`). These strings and their token ids are fixture `g0`.

## 3. Per-slice reference tensors, sizes, tolerances

Conventions for the tables: **NCL vs NLC is stated per tensor** (the upstream PyTorch path is
NLC for latents `[B,T,64]` and NCL for VAE audio `[B,2,S]`; the upstream MLX port uses NLC —
the fixture writer must not silently transpose, the README says which); float32 in the tiny
tier unless stated. "cos" is cosine similarity, `relL2 = ‖a−b‖/‖b‖`. Reuse the app's existing
helpers `KleinCosine.cosine` / `Flux2KleinEncoderQuantizationTests.relL2`
(`MLXUITests/Flux2KleinRealDiTGoldenTests.swift:36-44`).

### 3.1 Tokenizer + prompt formatting (slice 3c) — exact, no tolerance

| Tensor/key | Shape | From | Size | Tolerance | Why |
|---|---|---|---|---|---|
| `g0.prompt`, `g0.text_prompt`, `g0.lyrics_text` | strings | fixture constants | ~1 KB | **exact string equality** | formatting is pure string assembly; a drift here poisons everything downstream and is invisible in a cosine |
| `g0.text_input_ids` | `[Lt]` int32 | Qwen3 tokenizer, max 256 | ≤1 KB | **exact** | pins the tokenizer + SFT template |
| `g0.lyric_input_ids` | `[Ll]` int32 | same tokenizer, max 2048 | ≤1 KB | **exact** | pins the lyric header format |
| `g0.pad_token_id` | scalar | tokenizer config | 8 B | exact | padding value must match (affects `embed_tokens` row) |

Real-weight test: tokenize the same strings with the installed `Qwen3-Embedding-0.6B/tokenizer.json`
via `HFTokenizerLoader` (`MLXUI/Core/HFTokenizerLoader.swift`, `addSpecialTokens: false`) and
compare ids exactly. Skipped when the model isn't installed (env var or Direct store) — same
gating as the RIFE parity suite. The `# Metas` value is the caller's metadata block
(`bpm:`/`duration:`/`keyscale:`/`language:`/`timesignature:`, `code-map.md` Q1.1); the fixture
pins `metas = ""` for v1 (the no-LM row supplies no metadata) and one non-empty case in `g0` so
the serializer is covered.

### 3.2 Text encoder (slice 3c)

**Do not hand-write a Qwen3 forward.** The pinned `mlx-swift-lm 3.32.3` exposes exactly the
needed tensor through MLXEmbedders: `EmbedderTypeRegistry`/`EmbedderModelFactory` →
`Qwen3Model.callAsFunction(...)` → `EmbeddingModelOutput.hiddenStates` = post-final-RMSNorm
`[B,L,1024]`, and the app already calls that same prototype (`Modules/Embedding/EmbeddingEngine.swift:44-47`).
Recommendation and API-gap detail: `text-encoder.md` §2-§3. The one gap: the **lyric embedding
table** (`embed_tokens` for the lyric ids) is `private` inside MLXEmbedders' `Qwen3Model`, so
the port loads a separate `Embedding(151669, 1024)` from the same `model.safetensors` tensor
(155.31 M params, ~0.3 GB bf16) — `text-encoder.md` §3 caveats.
Consequence for the fixtures: **the Qwen3 trunk is a library call, so it is covered by a real-
weights test, not by a committed tiny-weights tap** (the app already trusts MLXEmbedders, and a
hand-rolled tiny Qwen3 fixture would test the library, not our code). The committed tiny file
only covers *our* pieces: the projector wiring and the lyric-table lookup.

| Tensor | Shape (tiny / real) | From | Size (tiny / real) | Tolerance | Why |
|---|---|---|---|---|---|
| `in.text_ids` | `[1,Lt]` / `[1,L]` | `g0.text_input_ids` (tiny ids: `% 64`) | tiny / 4 KB int32 | exact input | ids are pinned by `g0` |
| `in.lyric_ids` | `[1,Ll]` / `[1,Ll]` | `g0.lyric_input_ids` | tiny | exact input | |
| `w.projector` | `[8,4]` tiny random | `text_projector` (1024→2048, **no bias**) | 128 B | tiny max\|Δ\| ≤ 1e-6 | ours, not the library's |
| `out.text_hidden` | `[1,Lt,4]` tiny / `[1,L,1024]` real (f32) | MLXEmbedders `hiddenStates` | tiny / up to 0.4 MB f32 at L≈100 | tiny exact-ish; real **f32↔f32: cos ≥ 0.99999, relL2 ≤ 1e-5**; if the port computes bf16: cos ≥ 0.9995, relL2 ≤ 0.02 | reference runs the text encoder in **f32** on MPS (`init_service_orchestrator.py:101`, `text-encoder.md` §1.1); the parity target is f32 |
| `out.lyric_embed` | `[1,Ll,4]` tiny / `[1,Ll,1024]` real | separate `Embedding` gather | tiny / 0.16 MB f32 | tiny max\|Δ\| ≤ 1e-6; real cos ≥ 0.999999 | pure gather; any error is an index/table bug |
| `mid.projected` | `[1,Lt,8]` tiny / `[1,L,2048]` real | `text_projector(text_hidden)` | tiny / 0.8 MB f32 | tiny 1e-6; real cos ≥ 0.99999 | this is the tensor the condition encoder actually consumes, and it is ours |

Real-tier dumps: `real_text.safetensors` with `text_hidden` (full f32), `lyric_embed` (first/last
8 rows + full norm stats, or full — uncommitted, size is not the constraint), `projected`.
Test tiers: the real suite is env-var gated like `Flux2KleinRealDiTGoldenTests.swift:7-24`.

### 3.5 Full 8-step denoise (slice 3f) — the smallest fixture that pins the sampler

Do **not** try to reproduce the reference's RNG. On Apple Silicon the reference uses the
native MLX DiT and draws the noise with `mx.random.key(seed)` / `mx.random.normal`
(`acestep/models/mlx/dit_generate.py:295-308`); the torch path uses
`torch.Generator().manual_seed(seed)` (`modeling_acestep_v15_turbo.py:1780-1818`). No Swift
`MLXRandom` stream will match either, and even the two references differ. Instead the fixture
**ships the noise tensor itself** (`in.noise`) and the Swift sampler accepts injection — exactly
the Klein seam `Flux2KleinInjection.noise` (`Flux2KleinEngine.swift:60-70`, used by every tiny
test). The app-visible seed→noise mapping is then tested for *determinism*, not cross-framework
parity: same seed twice → bit-identical audio.

| Tensor | Shape (tiny / real) | From | Size (tiny / real) | Tolerance | Why |
|---|---|---|---|---|---|
| `in.noise` | `[1,16,8]` / `[1,250,64]` | the reference MLX `mx.random.normal(key)` draw (`dit_generate.py:295-308`) written out by the generator | 64 KB real | input | the RNG bridge is deliberately not compared |
| `schedule.timesteps` | `[8]` | `1−i/8` with `shift = 1.0` → `[1.0, 0.875, 0.75, 0.625, 0.5, 0.375, 0.25, 0.125]` (`:1970-1979`; `inference.py:151`; `SHIFT_TIMESTEPS[1.0]`, `code-map.md` Q5.1) | 32 B | **exact float32** (or ≤1e-7) | pure arithmetic; a wrong shift order changes every step |
| `step.x_{k}` | `[1,16,8]` / `[1,250,64]` ×9 | `x_0 = noise`; after each Euler/DCW step | 576 KB real | tiny max\|Δ\| ≤ 1e-5; real **cos ≥ 0.99 on x_8**, relL2 ≤ 0.10; also per-step cos printed | bf16 error compounds over 8 steps; the *trajectory* is what tells you whether the divergence is acceptable drift or a wrong formula |
| `step.v_{k}` | `[1,16,8]` / `[1,250,64]` ×8 | each step's `v` | 512 KB real | tiny 1e-5; real cos ≥ 0.998 per step | isolates sampler vs model: `v_0` should already be at the single-forward tolerance |
| `dcw.on` (bool) + `dcw.x_{k}` / `dcw.denoised_{k}` | ×8 | DCW **on** (turbo default), haar, scalers 0.05/0.02 | ~1.1 MB real | tiny 1e-5; real cos ≥ 0.99 | the default turbo path includes DCW (`generate_music.py:181-195`); a port without it will *not* match the reference end-to-end |
| `dcw.off.x_8` | `[1,16,8]` | same loop, `dcw_enabled=False` | small | tiny 1e-5 | proves the correction is wired to the flag, and gives a cheaper reference if the owner ever rules DCW out of v1 |
| `step.final` | `[1,16,8]` / `[1,250,64]` | last step's direct x0 jump (`:2138-2147`) | | same as `x_8` | the final-step formula is different from the other seven; pin it explicitly |

T = 250 (10 s) is the reference's own minimum duration (`DURATION_MIN = 10`, `constants.py:58-59`),
it is divisible by patch 2, and 250 > the 128-token sliding window, so the sliding mask is
non-trivial. (A T = 200/8 s clip would be *outside* what the reference accepts; the app's Run UI
can offer a shorter duration only as a deliberate divergence, not a parity target.)
Tiny T = 16 with `sliding_window 8` keeps the same property.

### 3.6 VAE decode (slice 3g) — and encode only if the port ever does covers

Real VAE: `AutoencoderOobleck`, 48 kHz, stereo, hop 1920, latent 64-d. 2 s of audio = 96 000
samples = 50 latents. Use **2 s**, not 8 s, in the committed tiny tier and in the real tier's
primary case: a 2 s decode is 0.77 MB float32, while a 10 s decode is 3.84 MB. **One extra
case must exist: a chunked decode.** The reference decodes in one shot when
`T <= mlx_chunk` and otherwise overlap-discards chunks (`mlx_vae_decode_native.py:88-140`;
chunk 512 latent frames / overlap 64 on an 18 GiB Mac, `gpu_config.py:779-806`), so the tiny
fixture includes a 3-chunk case proving the trim arithmetic against a one-shot decode of the
same latents.

| Tensor | Shape (tiny / real) | From | Size (tiny / real) | Tolerance | Why |
|---|---|---|---|---|---|
| `in.latents` | `[1,4,8]` NLC / `[1,50,64]` NLC | fixed, ~N(0,1) | tiny / 12.8 KB | input | |
| `w.*` | all 365 tensors in the reference `weight_g`/`weight_v`/Snake/snake/bias form | reference `AutoencoderOobleck` tiny config (weight_norm kept!) | tiny / **not committed**; real file read from the install | — | the Swift port must fuse `weight_g,weight_v → weight` and reorder convs; fixtures must keep the *reference* layout so that mapping is tested (`findings/inventory/names_vae.txt:4-20`) |
| `mid.dec_block_{i}` | `[1,C,Si]` NCL | decoder block output after each of the 4/5 blocks | small | tiny 1e-5; real cos ≥ 0.999 | conv/snake stack bugs are localised per block |
| `out.audio` | `[1,2,1920]` / `[1,2,96_000]` NCL float32, clamped/py-normalised as `generate_music_decode.py:190-196` | `vae.decode` | tiny 15 KB / **0.77 MB** | tiny max\|Δ\| ≤ 1e-5; real cos ≥ 0.999, max\|Δ\| ≤ 0.02 | bf16 conv stack; the reference's `peak>1 → divide` normalisation is part of the expected output |
| `enc.in_audio` | `[1,2,1920]` / `[1,2,96_000]` | same audio | | input | **only if 3g includes encode** (covers/repaint). v1 text2music does not need it — the plan still fixtures `encode_mean` because prompt-to-audio without it cannot be extended later without a new dump |
| `enc.mean` | `[1,4,8]` / `[1,64,50]` NLC | `encode_mean` (deterministic; not `encode_and_sample`, which draws noise) | tiny / 51 KB | tiny 1e-5; real cos ≥ 0.999 | pin the deterministic half only; sampling noise is not parity-testable |

### 3.7 End-to-end 10 s audio (slice 3h) — optional, loose

Full pipeline: format → tokenize → text encoder → condition encoder → noise → 8-step DCW
denoise → VAE decode → stereo 48 kHz, 10 s. Two fixtures:

1. **Committed tiny e2e** (must exist; it is the slice's done-when): tiny modules from
   §3.1–3.6, T = 16 → 30 720 samples nominal in the tiny VAE config (or a 4× downsample
   toy VAE to keep it ~30 KB). Tolerance: **max|Δ| ≤ 1e-5 against the reference tiny chain**
   (fp32, same math). This is the test that catches a *wiring* error (order of stages, wrong
   tensor handed between stages, off-by-one in the final step) that per-stage fixtures pass.
2. **Real e2e, env-var gated, not committed**: 10 s (the reference minimum), prompt/lyrics/settings
   from §1, seed 20261107, reference produced by the pinned upstream code with **the reference's
   own noise tensor written out** (`real_e2e/noise.safetensors`, 64 KB) and the resulting stereo
   float32 audio `real_e2e/audio.f32` (3.84 MB, not committed).

| Check | Tolerance | Why |
|---|---|---|
| shape / duration | `[1,2,480_000]`, exactly 10.000 s | duration arithmetic (`T = round(s·25)`, `S = T·1920`) is exact |
| no NaN/Inf, peak ≤ 1.0 | — | the reference normalises peak > 1 (`generate_music_decode.py:190-196`); a peak > 1 in the port means the step is missing |
| whole-waveform cosine | ≥ 0.99 | bf16 + 8 compounded steps; two frameworks will not be sample-identical |
| per-0.25 s RMS ratio (ours/theirs) | 0.85…1.15 | absolute sample alignment is too fragile; energy-envelope parity is what a listener hears |
| mel-spectrogram cosine (64 mels, 0.1 s hop) | ≥ 0.99 | same reason; catches "sounds right but wrong pitch content" |
| first 0.5 s raw waveform cosine | ≥ 0.99 | the start is least affected by accumulated drift; gives a tight check on the VAE decode path |

The **same-framework fallback**: because the upstream tree ships an MLX DiT + VAE, the owner
can also dump `real_denoise` / `real_vae` from `acestep/models/mlx/dit_generate.py` and
`vae_model.py`. MLX→MLX tolerances are tighter (cos ≥ 0.9999, relL2 ≤ 1e-3) and any gap there
is a Swift bug, not a framework gap. The Swift port must pass **torch** parity (loose) first;
the MLX cross-check is diagnostic only. (It does not cover the text encoder or condition
encoder — those stay torch-only.)

## 4. How the reference dumps are generated (script sketch, not run)

Three scripts live in `MLXUITests/Fixtures/ACEStep/` (RIFE puts its generator there too,
`make_rife_golden.py`). A pinned venv is described by `requirements.txt` + `versions.json`:
`torch 2.9.1`, `diffusers 0.37.1`, `transformers 4.57.3`, `safetensors`, `numpy 2.2.6`
(the exact pins Flux2Klein already proved reproduce byte-identically,
`Fixtures/Flux2Klein/requirements.txt`, `versions.json`). The repo's own
`pyproject.toml:59-60` requires `pytorch-wavelets>=1.3.0`/`pywavelets>=1.9.0` for DCW — pin them
too, and **assert `DCWCorrector.is_active`** in the generator (a silently missing wavelet
package makes the reference no-op and the fixtures would pin the wrong path).

`make_aces_step_tiny_goldens.py` (sketch — ~300 lines, modelled on
`Fixtures/Flux2Klein/tiny_goldens.py`):

```python
"""Tiny-config parity goldens for the ACE-Step 1.5 port (MC5). Scratch tool, not part of the app.
Builds random-init fp32 modules from the upstream PyTorch classes at TINY sizes, fixed seed,
no real weights, no network. Usage: python3 -I make_aces_step_tiny_goldens.py <upstream-repo> <out_dir>
"""
import argparse, hashlib, json, sys, torch
sys.path.insert(0, sys.argv[1])                     # the pinned upstream tree (its own class files)
from acestep.models.turbo.configuration_acestep_v15 import AceStepConfig   # + model classes
from acestep.models.turbo.modeling_acestep_v15_turbo import (...)
from safetensors.torch import save_file
SEED, OUT_BUDGET = 20261107, 10 * 1024 * 1024
torch.manual_seed(SEED); torch.set_num_threads(1)   # one thread = byte-identical reruns
# 1. tiny configs: TINY_COND (hidden 32,
#    text_hidden_dim 16, timbre_hidden_dim 8, lyric 2 / timbre 1 layers, window 4),
#    TINY_DIT (hidden 32, 2 layers, patch 2, in_channels 24, heads 4/KV 2/head 8),
#    TINY_VAE (AutoencoderOobleck: block_out_channels (8,8,16), downsampling_ratios (2,2,2))
# 2. randomise weights N(0, 1/fan_in) so every residual branch has real size (Klein did this)
# 3. g0: build the real prompt/lyrics strings with the REAL tokenizer (no network: pass a
#    tokenizer folder as argv[3], or commit only the strings and tokenise with
#    transformers.AutoTokenizer from the downloaded Qwen3-Embedding folder); write ids/masks.
# 4. g1: OUR pieces only — a tiny text_projector (1024→2048 analogue) applied to a random
#    hidden, and a lyric embed gather; the Qwen3 trunk itself is MLXEmbedders (real test).
# 5. g2: run the tiny condition encoder on g1's outputs; dump every stage tap + the packed seq.
# 6. g3: one tiny DiT forward at t=1.0 and t=0.4 (alt.*); dump inputs, temb, timestep_proj,
#    patch_in, block_out[i] for i in range(n), cross K/V of layer 0, pred.
# 7. g4: the 8-step loop copied verbatim from modeling_acestep_v15_turbo.py:1937-2210
#    (schedule shift=1.0, euler, final x0 jump, DCWCorrector on and off), dumping x_k/v_k/dcw
#    taps. Noise is drawn ONCE and written as an input; the dtype used for the loop is printed
#    and recorded in versions.json (see the f32/bf16 trap below).
# 8. g5: tiny AutoencoderOobleck, encode_mean(audio), decode(latents); dump reference
#    weight_g/weight_v/alpha/beta unchanged (do NOT pre-fuse: the Swift fuse is what's tested).
# 9. g6: tiny end-to-end by calling the *reference classes'* own methods in the same order the
#    handler does (conditioning_text.py → conditioning_embed.py → generate_audio → decode);
#    dump the final audio + every inter-stage hand-off.
# every dump() writes one safetensors with ONE metadata key (Klein README: 2+ keys make header
# bytes vary and break the sha256); asserts total <= OUT_BUDGET; prints sha256 of every file.
```
Determinism: fixed seed, fp32, `torch.set_num_threads(1)`, only one metadata key, no
timestamps/no network — the same recipe the Klein README documents (`:3-7`, `:20-30`).
Run twice in CI-ish fashion before committing; the README pins the second-run SHA-256s.

`make_aces_step_real_goldens.py` (owner-run, output not committed): takes
`<weights_dir> <out_dir>` where the weights dir is the full `Ace-Step1.5/` checkout; loads the
real components with the reference classes (`transformers.Qwen3Model`,
`AceStepConditionGenerationModel`, `AutoencoderOobleck`) and **runs exactly the reference
pipeline the app's harness runs** (`run_generate_test.py` / the code in `run-notes.md` §1):
`GenerationParams(task_type="text2music", caption=…, lyrics="[instrumental]", instrumental=True,
duration=10.0, vocal_language="en", inference_steps=8, shift=1.0, infer_method="ode",
guidance_scale=1.0, seed=20261107, thinking=False, …)` + `GenerationConfig(batch_size=1,
use_random_seed=False, seeds=[20261107], audio_format="wav")`, with **no `LLMHandler`** (a
no-LM run — `run-notes.md` §3). That also gives the end-to-end reference the app will compare
against. It dumps the **same key names** as the tiny tier so the Swift comparison is one
function per slice.

**Record the dtype actually used — this is the one place the sources disagree.** The native
MLX DiT converter upcasts to f32 (`acestep/models/mlx/dit_convert.py:39`), and the MLX-port
analysis makes the same call: "the Python port runs the DiT in **float32** … ~9.6 GB for 2.4B"
(`swift-gaps.md` §0.5), while an early harness patch (`out/smoke.json` `"patches"`) reported a
**bfloat16** native MLX DiT built from the same file.
The text encoder reference is f32 on MPS (`init_service_orchestrator.py:101`); the MLX VAE
reference is f32 by default (`ACESTEP_MLX_VAE_FP16` opt-in, `mlx_vae_init.py:48-57`). The
generator must **print and write `dtypes` into `versions.json`**, and the tolerance is chosen
from the dtype that actually ran, not assumed: f32↔f32 → max|Δ| ≤ 1e-5; bf16↔bf16 →
cos ≥ 0.998; int8 ≥ 0.995; int4 ≥ 0.93 (the last three are Klein's measured figures,
`Flux2KleinRealDiTGoldenTests.swift:30-34`; re-pin after the first run — a limit set before
measuring is a guess).

Also generate the **timestep schedule** independently of the model (`g4_scalars.json` with the
8 floats + the linspace/shift formula cross-check), like Klein's `g3f_scalars.json`.

conversions (`asType(.float32)`) so a bf16 fixture is compared through one explicit cast.

## 6. Risks and open questions (Q11)

- **Q11-1 (spec ambiguity, must be asked):** is skipping `tokenize→detokenize` for
  `is_covers == 0` allowed? The reference computes it and discards it (`:1650-1690`). Output is
  identical for text2music; the port saves the FSQ/pooler/detokenizer weights (~0.2 GB and a
  lot of code). Recommend: skip, mark `// SPEC-Q` and a test asserting the discard path is
  not exercised for text2music. If the owner ever wants covers, that path needs its own slice.
- **Q11-2:** DCW is part of the turbo reference default but is *not* needed to "generate
  music" in the app's sense, and it adds `pytorch-wavelets` parity risk. The fixtures pin both
  (`dcw.on`/`dcw.off`); if the owner rules DCW out, the end-to-end fixture must be generated
  with `dcw_enabled=False` and the listening review happens on that output. Decide **before**
  the real dumps are made (the dumps are once-only), or dump both (cheap: 8×51 KB extra).
- **Q11-3:** the RNG bridge is not parity-testable. The port must accept an injected noise
  tensor (fixtures) and separately guarantee "same seed twice → byte-identical audio". A
  user-visible seed will *not* reproduce the reference app's audio for the same integer seed —
  say so in the row's notes rather than implying cross-implementation reproducibility.
- **Q11-4:** dtype per stage, not one dtype. Reference dtypes on this Mac: text encoder **f32**
  (`init_service_orchestrator.py:101`), VAE **f32** by default (`mlx_vae_init.py:48-57`), DiT
  f32 in the code but reported bf16 in the Lead's smoke harness (`out/smoke.json` `patches`);
  the committed tiny tier is f32 throughout. The tolerance table is keyed to the dtype that
  actually ran — record every stage's dtype in the fixture README and `versions.json`, because
  a dtype mismatch masquerades as a tolerance failure.
- **Q11-5:** the 12 GB process cap (decision 4) does not change the fixtures; it changes
  *which* real runs are dumped (no-LM vs +0.6B/1.7B LM). The LM path (5 Hz LM → audio-code
  hints → `precomputed_lm_hints_25Hz`) is **out of Q11's slice set for v1**; if a later slice
  adds it, it needs its own goldens from `acestep/models/turbo/modeling_acestep_v15_turbo.py`'s
  `precomputed_lm_hints_25Hz` input and the LM class in `acestep/llm_inference.py`.
- **Q11-6:** end-to-end real audio is ~3.8 MB and only reproducible from the pinned upstream
  tree with the pinned venv on the **same Mac** (the Swift side runs here too). The reference
  is deterministic with `infer_method="ode"` and a fixed seed; do **not** generate it with
  `infer_method="sde"` (unseeded renoise, `modeling_acestep_v15_turbo.py:2150-2156`) or with
  the LM on (`run-notes.md` §6.2: the single-item LM path has no seeding).
- **Q11-7 (evidence gap):** the reference DiT dtype depends on which path the generator runs —
  the MLX conversion upcasts to f32 (`dit_convert.py:39`; `swift-gaps.md` §0.5 says the Python-MLX
  DiT is f32, "~9.6 GB for 2.4B"), while the Lead's early harness patch says bf16
  (`out/smoke.json`). The generator must print it; do not author the DiT real tolerances until one
  run has recorded it. The Swift port's own dtype is a separate decision: it should load **bf16**
  (3.15 GB) or **quantize** (int8/int4), because a faithful f32 DiT is 9.6 GB and cannot fit the
  12 GB cap with anything else. Note the upstream MLX path **never quantizes**, so int8/int4 have
  no Python-MLX oracle — their tolerances are measured against the f32 reference after the fact
  (Klein's int8/int4 figures are the only prior).
- **Q11-8 (quality gate, not parity):** the `mlx-community/ACE-Step1.5-MLX` card claims the
  5 Hz LM "is required for the turbo model to produce music", while the official reference
  supports a no-LM text2music run and the Lead's smoke with `lm: "none"` produced WAVs
  (`out/smoke.json`). Parity fixtures cover the no-LM path (that is what v1 ports); whether the
  no-LM output is *acceptable music* is the owner's listening review (MC5-3i), not a cosine
  test. Do not let the fixture suite substitute for it.
- **Q11-9:** if a later slice adds cover/repaint, the VAE **encode** path and the
  tokenizer/pooler/FSQ/detokenizer fixtures become load-bearing; this plan dumps `encode_mean`
  now (cheap) so that path is not blocked, but the `encode_and_sample` noise draw is not
  parity-testable (same RNG argument as Q11-3).
